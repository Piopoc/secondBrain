# Analysis of WA - 02

## Overview
The documents in the `WA - 02` folder provide a comprehensive overview of the evolution of the World Wide Web and the architectural patterns used in distributed applications. The material covers the historical precursors to the web, the progression from Web 1.0 to Web 3.0, the distinction between the Internet and the Web, and a detailed comparison of single-tier, two-tier, and multi-tier (n-tier) architectures.

## Detailed File Analysis

### image0.jpg
This file focuses on the history and evolution of the web, as well as the basics of distributed application logic.

**1. History of the Web**
- **Vannevar Bush:** Conceptualized the **Memex**, an abstract machine for storing books and communications to facilitate rapid research.
- **Ted Nelson:** Developed **Project Xanadu**, introducing the concept of **HyperText** for non-linear presentation of material. He identified key challenges such as bi-directional links, transcopyright, versioning, and preserving original context.
- **Douglas Engelbart:** Created the **NLS System**, inventing the mouse and pioneering the use of hyperlinks, windows, and presentation programs.
- **Tim Berners-Lee:** Created the **World Wide Web (WWW)**, simplifying previous complex systems by introducing a set of universal and scalable standard protocols: **HTTP**, **HTML**, and **URL**.
- **Browsers:** Act as the graphical interface to visualize these hyperlinks.

**2. Evolution of the Web**
- **Web 1.0 (Read Web):** Characterized by static pages and passive consumption of information. Utilized HTTP, HTML, MIME, and URI.
- **Web 2.0 (Read & Write Web):** Introduced dynamic participation and user-generated content (e.g., social media). Key technologies include XML, AJAX, JSON, SOAP, and REST, with a direct mapping of JavaScript objects to HTTP clients.
- **Web 3.0 (Semantic Web / Web of Data):** Focuses on data control and the removal of centralized intermediaries. It uses structured data to make information machine-readable via **RDF**, **OWL**, and **SPARQL** (Data model $\rightarrow$ Schema $\rightarrow$ Query language).
- **Web3:** A decentralized system where data is controlled by the users.

**3. Web Concepts**
- **Deep Web:** Content that cannot be indexed by standard search engines, often consisting of dynamic/parametric URLs or data stored in relational databases.
- **Dark Web:** A portion of the web requiring specific software (e.g., Tor, I2P) for anonymous and confidential access, often associated with illegal activities.
- **Internet vs. Web:** The **Internet** is the underlying physical and logical infrastructure (network of PCs), while the **Web** is a service that runs on top of that infrastructure.

**4. Distributed Applications - Logical Levels**
Modern web applications separate logic into three levels:
- **Data Logic:** Manages permanent storage, retrieval, and ensures data consistency.
- **Application Logic:** Manages the system core, flow operations, and enforces business rules.
- **Presentation Logic:** Manages the User Interface (UI) and validates user input.

**5. Single-tier Architecture**
- **Structure:** All three logical levels (Presentation, Application, Data) reside on a single central system (e.g., a Mainframe).
- **Pros:** Simple implementation; no need to manage remote terminals.
- **Cons:** The entire load is on the mainframe; poor scalability.

### image1.jpg
This file details the different tiers of distributed architectures and their application to web services.

**1. Two-tier Architecture**
- **Fat Client / Server:** Presentation and Application logic are handled by the client, while Data logic resides on the server.
    - **Pros:** Easy to implement; possibility to balance load.
    - **Cons:** High client maintenance overhead; limited scalability.
- **Client / Fat Server:** Presentation logic is on the client, while Application and Data logic are on the server.

**2. Three-tier (m-tier) Architecture**
- **Structure:** Separation into a **Thin Client** (Presentation), an **Application Server** (Application logic), and a **Database Server** (Data logic).
- **Pros:** Easy client maintenance; high scalability; efficient load balancing.
- **Cons:** Higher implementation complexity.

**3. Web Applications**
Web applications are a specific instance of the 3-tier architecture. They are ubiquitous, accessible from any device without requiring client-side management, and rely on standardized server-side technologies.

**4. The Web Application Stack**
The material illustrates the interaction between the **Web Application Stack** (Client $\leftrightarrow$ Server via Request/Response) and the underlying **Network Stack**:
- **Application Layer:** HTTP
- **Transport Layer:** TCP/UDP
- **Network Layer:** IP
- **Physical Layer:** Host-Physical

## Synthesis
The files trace a logical progression from the conceptual desire for non-linear information retrieval (Bush, Nelson) to the technical implementation of the Web (Berners-Lee). This evolution is mirrored in the architectural shift of applications: moving from centralized, single-tier systems (Mainframes) to distributed multi-tier architectures. The 3-tier model is the foundation of the modern web, allowing for the scalability and ubiquity that define Web 2.0 and the emerging decentralized nature of Web 3.0/Web3.
