# Analysis of WA - 06

## Overview
The folder `WA - 06` contains handwritten notes and a sequence diagram detailing the architecture of a full-stack Java application. The focus is on the 3-tier architectural model, the implementation of the Data Access Object (DAO) pattern, the use of Java Beans for data transport, and the optimization of database connectivity through connection pooling and JNDI.

## Detailed File Analysis

### image0.jpg
This file provides the foundational theory and a high-level architectural overview.

- **3-Tier Architecture**: The system is divided into three distinct layers:
    - **Presentation Logic (Client)**: Handles the user interface.
    - **Application Logic (Server)**: Manages business rules and coordinates data flow.
    - **Data Logic (Database)**: Handles persistent storage.
- **DAO Pattern**: 
    - **Goal**: To decouple the application logic from the underlying data source.
    - **Structure**: Each resource has a dedicated DAO implementing a generic `DataAccessObject<T>` interface.
    - **AbstractDAO**: A base class that provides uniform behavior for all DAOs, specifically managing connection opening and ensuring resources are released using `try-catch-finally` blocks to prevent memory leaks.
- **Resource Classes (Java Beans)**:
    - Used to model and transport data between tiers.
    - **Immutability**: These objects are designed to be immutable (no setter methods) to ensure thread safety, which is critical in a Servlet environment where race conditions are a primary concern.
- **Connection Pooling & JNDI**:
    - **Issue**: Establishing a database connection is a "heavy" operation (socket opening, authentication), creating a bottleneck.
    - **Solution**: A connection pool is maintained (managed by Tomcat) to keep connections open.
    - **JNDI (Java Naming and Directory Interface)**: Used to avoid hardcoding database credentials (IP, password, port) in the source code. Servlets perform a "lookup" to retrieve the pool configuration from the container.
- **Sequence Diagram**: Illustrates the flow for searching employees by salary:
    - `SearchEmployeeBySalaryServlet` (extending `AbstractDatabaseServlet`) initializes by obtaining a datasource via JNDI.
    - The servlet requests a connection, instantiates a `SearchEmployeeBySalaryDAO`, and calls its `access()` method.
    - The DAO executes a `SELECT` statement, processes the `ResultSet` into a list of `Employee` beans, and returns them.
    - The servlet then generates an HTML response.

### image1.jpg
This file delves into the specific class implementations and configuration details.

- **Class Specifications**:
    - `Employee` Class: Uses `final` and `private` fields to ensure immutability and prevent concurrency issues.
    - `Message` Class: Used for transporting business logic results, including informative messages and errors.
    - `AbstractDAO`: Manages potential DAO misuse or leakage using a `lock` object and an `accessed` flag.
    - `CreateEmployeeDB` & `SearchEmployeeBySalaryDAO`: Both emphasize the use of `PreparedStatements` to prevent SQL injection attacks.
- **Configuration (`context.xml`)**:
    - This file defines the database connection pool settings, including the JNDI resource name, authentication parameters (managed by the container), JDBC driver (PostgreSQL), and the database URL.
    - The `web.xml` file provides the link to this configuration.
- **Servlet Implementation**:
    - `AbstractDBServlet`: Handles the lifecycle of the connection pool (`init()` for lookup, `destroy()` for cleanup) and provides `getConnection()` for subclasses.
    - `CreateEmployeeServlet`: Extracts request parameters, creates an `Employee` bean, and uses a DAO to persist the data.
    - `SearchEmployeeBySalaryServlet`: Uses a DAO to retrieve a list of `Employee` beans based on salary and renders the result as HTML.

## Synthesis
The files collectively describe a robust, enterprise-grade Java architecture. The interconnection is centered around the **DAO pattern**, which bridges the gap between the **Application Logic (Servlets)** and the **Data Logic (Database)**. 

The architecture prioritizes:
1. **Security**: Using `PreparedStatements` to thwart SQL injection and JNDI to hide sensitive credentials.
2. **Performance**: Implementing connection pooling to eliminate the overhead of repeated connection establishment.
3. **Stability**: Enforcing immutability in Java Beans to ensure thread safety in a multi-threaded environment and utilizing `finally` blocks in `AbstractDAO` to prevent resource leaks.
4. **Maintainability**: Using an abstract base class (`AbstractDAO` and `AbstractDBServlet`) to centralize common logic and ensure uniform behavior across the application.
