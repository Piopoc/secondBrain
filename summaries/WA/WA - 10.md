# Analysis of WA - 10

## Overview
The folder `WA - 10` contains handwritten notes providing a comprehensive introduction to markup languages. The content evolves from the general definition of "marking up" text to specific, widely-used standards for web content and data interchange, specifically SGML, HTML, XML, and JSON.

## Detailed File Analysis

### image0.jpg
This file introduces the fundamental concepts of markup and the first three major languages:
- **Markup Fundamentals**: Defines markup as the act of adding marks to text. It categorizes markup into several types:
    - **Punctuation**: Syntactic information.
    - **Presentational**: Layout and visual arrangement.
    - **Procedural**: Formatting commands.
    - **Descriptive**: Defining the type or class of content.
    - **Referential**: Linking to external entities.
    - **Meta-markup**: Controlling the interpretation of other markup.
- **SGML (Standard Generalized Markup Language)**: A meta-markup language that serves as the basis for others (like HTML and XML). It introduced the concept of Document Type Definitions (DTD).
- **HTML (HyperText Markup Language)**: An application of SGML used for creating web pages. It combines procedural, descriptive, and referential markup. The notes highlight issues such as loose parsing and the lack of separation between content and presentation in older versions (HTML 4.0).
- **XML (Extensible Markup Language)**: A semi-structured data representation language geared towards interoperability. It is a typed language that can be defined via DTD or XML Schema.
    - **XML Tree Structure**: Documents are represented as trees consisting of nodes: `TEXT`, `ELEMENT`, `ATTRIBUTE`, `COMMENT`, `PROCESSING INSTRUCTION`, and the `ROOT`.
    - **XML APIs**:
        - **DOM (Document Object Model)**: In-memory representation using IDL.
        - **SAX (Simple API for XML)**: Push-based streaming API using callbacks.
        - **StAX (Streaming API for XML)**: Pull-based streaming API.

### image1.jpg
This file delves deeper into XML structure definition and introduces JSON:
- **DTD (Document Type Definition)**: A method to define the structure of an XML document, specifying elements, attributes, and their constraints (order, quantity, optionality).
    - **Limitations of DTD**: Lack of data type support, context-independent declarations, non-XML syntax, and lack of namespace/auto-documentation support.
- **XML Namespaces**: Used to avoid element name conflicts, defined via the `xmlns` attribute.
- **XML Schema**: A more powerful alternative to DTD that uses XML syntax and supports simple and complex data types.
- **JSON (JavaScript Object Notation)**: A lightweight data interchange format based on two structures: objects (name/value pairs) and arrays (ordered lists).
    - **JSON Schema**: Used for validation, documentation, and interaction control.
    - **Parsing**: Often handled via pull streaming APIs (e.g., Jackson Project).

## Synthesis
The documents trace a logical progression in the evolution of data representation. It starts with the basic concept of markup, moves to the foundational meta-language SGML, and then branches into HTML for presentation and XML for structured data exchange. The notes contrast the rigid but limited DTD with the more flexible XML Schema, and finally introduce JSON as a more lightweight alternative to XML for modern data interchange, noting that both XML and JSON have corresponding schema languages for validation and structure definition.
