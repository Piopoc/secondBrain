# Analysis of WA - 08

## Overview
The folder `WA - 08` contains notes focusing on the **REST (Representational State Transfer)** architectural paradigm, its implementation in web services, and the use of **AJAX** for client-side communication with these services. The core theme is the transition from traditional data access (DAO) to a resource-oriented architecture exposed via HTTP.

This file contains comprehensive handwritten notes divided into four main sections:

#### 1. REST Architectural Paradigm
- **Definition**: REST stands for REpresentative State Transfer. It is an architectural paradigm that applies the principles of the Web to Web services to achieve simplicity, statelessness, and scalability.
- **Core Concepts**:
    - **Resource**: Any entity with a unique and global identifier (URI). Resources have a state that can change over time.
    - **Statelessness**: Every request from the client to the server must contain all the information necessary to understand and process the request, without relying on stored server-side context.
    - **Representation**: The server transfers a representation of the resource's state (e.g., JSON, XML) to the client.
- **Design Principles**:
    1. Identify resources to be exposed.
    2. Create descriptive URIs (preferably using nouns).
    3. Map HTTP methods (GET, POST, PUT, DELETE) to CRUD operations (Read, Create, Update, Delete).
    4. Use hypermedia (links) to navigate between resources.
    5. Define representation formats (schemas).
    6. Provide accurate documentation.
- **Protocol**: While REST is an architectural style, HTTP is the primary protocol used to implement it, providing a uniform interface.

#### 2. Development of REST Web Services
- **Implementation Details**:
    - **Resource Interface**: Use of an `AbstractResource` class with a `toJSON` method for serialization.
    - **JSON Handling**: Integration of `JsonParser` and `JsonGenerator` (configured via `pom.xml`).
    - **Service Layer**: A `RestResource` interface (similar to a DAO) and an `AbstractRR` class implementing `serve` and `doServe` methods, along with `checkMethodMediaType` for validation.
- **Infrastructure**:
    - **Duality**: The notes highlight a duality between the DAO (Data Access Object) and the RR (Resource Representation) classes.
    - **Configuration**: Use of `web.xml` to map the `/rest/*` URL pattern to a `RestDispatcherServlet` (or `RestManagerServlet`), which acts as the entry point for all REST requests.

#### 3. AJAX (Asynchronous JavaScript and XML)
- **Client-Side Integration**: Describes how to access a database indirectly via REST services using AJAX in a JSP page.
- **XMLHttpRequest Workflow**:
    1. Instantiate `XMLHttpRequest`.
    2. Define a callback function (`onreadystatechange`) to handle the server's response.
    3. Initialize the request using `xhr.open()` (specifying method, URL, and asynchronous flag).
    4. Send the request using `xhr.send()`.
- **Response Processing**:
    - Verify if the request is complete (`readyState === XMLHttpRequest.DONE`).
    - Check for a successful HTTP status code (e.g., `status === 200`).
    - Parse and elaborate on the received response.

## Synthesis
The materials in `WA - 08` illustrate a complete end-to-end flow for modern web communication. It starts with the **theoretical foundation** of REST (resources, URIs, statelessness), moves to the **server-side implementation** in Java (Servlets, `web.xml`, JSON serialization, and the RR pattern), and concludes with the **client-side consumption** using AJAX. The transition from DAO to RR emphasizes the shift from thinking about "data tables" to thinking about "web resources."
