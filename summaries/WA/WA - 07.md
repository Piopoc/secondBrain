# Analysis of WA - 07

## Overview
The folder `WA - 07` contains educational notes focusing on Java web development, specifically detailing the use of JavaServer Pages (JSP) and the implementation of the Model-View-Controller (MVC) architectural pattern.

## Detailed File Analysis

This file contains handwritten notes and diagrams explaining JSP and MVC.

#### 1. JavaServer Pages (JSP)
- **Definition**: JSP is a technology used to create dynamic web responses through textual specification.
- **Lifecycle**:
    - When a `.jsp` file is first requested, the web server translates it into a Java servlet (`.java` file) and compiles it into a class file (`.class`).
    - Subsequent requests use the compiled class file directly for efficiency.
- **Key Components**:
    - **Template Text**: Static HTML content.
    - **Directives**: Used to provide global information for the JSP page.
    - **Actions**: Standard or custom operations performed by the server.
    - **Scripting**: Raw Java code embedded in the page (noted as something to potentially avoid).
    - **Expression Language (EL)**: A simplified language for accessing application data and variables.
- **Supporting Technologies**:
    - **JavaBeans**: Reusable Java classes following naming conventions that can be manipulated within the application framework.
    - **JSTL (JSP Standard Tag Library)**: Provides a set of standard tags for common tasks (core, XML, formatting, database access, and functions). Dependencies for JSTL are managed in the `pom.xml` file.

#### 2. Model-View-Controller (MVC) Paradigm
The notes describe the MVC pattern both conceptually and through a practical implementation example.

- **Conceptual Model**:
    - **Model**: Manages the application state (implemented using JavaBeans).
    - **View**: Handles the presentation and visualizes the output (implemented using JSP, HTML, CSS, and JS).
    - **Controller**: Acts as the intermediary that manipulates the model based on user input (implemented using Servlets).
    - **Interaction Flow**: User $\rightarrow$ Controller $\rightarrow$ Model $\rightarrow$ View $\rightarrow$ User.

- **Practical Implementation Example**:
    - **Views**: Split into "FORM" views (e.g., `create-employee-form.jsp`) for input and "RESULT" views (e.g., `create-employee-result.jsp`) for output.
    - **Controller**: Servlets (e.g., `CreateEmployeeServlet`) handle POST requests from the form views.
    - **Model & Data Logic**: The controller invokes Data Access Objects (DAOs) like `CreateEmployeeDAO` to interact with the Model (e.g., `Employee` class).
    - **Response**: The controller forwards the request to the appropriate result view to display the outcome to the user.

## Synthesis
The files demonstrate the transition from basic dynamic page generation (JSP) to a structured architectural approach (MVC). JSP provides the View layer, Servlets provide the Controller layer, and JavaBeans/DAOs provide the Model layer. This separation of concerns ensures that the business logic (Model), user interface (View), and request handling (Controller) are decoupled, making the application more maintainable and scalable.
